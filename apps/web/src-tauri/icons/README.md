# Tauri Icons

> **Status**: Default Tauri placeholder icons in place. Custom icon generation is **manual** and **out of scope** for the current Tauri integration work.

## Current State

The 16 files in this directory are the **default Tauri v2 placeholder icons** generated by `cargo tauri init` (T2 in the integration plan). They are not production icons — they render as Tauri's default gray "T" logo and must be replaced before shipping a release.

The five files referenced by `tauri.conf.json` > `bundle.icon` are:

| File             | Platform                   |
| ---------------- | -------------------------- |
| `32x32.png`      | Linux / Windows small icon |
| `128x128.png`    | Windows medium icon        |
| `128x128@2x.png` | macOS retina icon          |
| `icon.icns`      | macOS `.icns` bundle       |
| `icon.ico`       | Windows `.ico` bundle      |

The remaining 11 files (`icon.png`, `Square*Logo.png`, `StoreLogo.png`) are platform-specific variants used by the Windows Store / MSIX packaging targets. They will be regenerated automatically when you run the icon command.

## How to Replace with Custom Icons

The Tauri CLI ships an `icon` subcommand that takes a single source PNG and regenerates **all** platform variants in this directory.

### Source requirements

- **Size**: 1024 × 1024 pixels (square)
- **Format**: PNG
- **Transparency**: **none** (opaque background — Tauri 2 rejects transparent source images)
- **Color profile**: sRGB recommended

### Command

Run the command from the web app directory, pointing at the source PNG:

```bash
cd apps/web
bun run tauri icon ./path/to/source.png
```

This invokes the JavaScript Tauri CLI installed in T5 (`@tauri-apps/cli@2.11.2` — exposed via the `tauri` binary in `node_modules/.bin/`). The same binary is reachable as `bunx tauri icon` or `npx tauri icon` if you prefer.

> **Do not use `cargo tauri icon`.** That form works only when `cargo-tauri` is on the system PATH and the user is inside `src-tauri/`. The JavaScript CLI is the canonical entry point for this project and matches the tooling wired up by the integration plan.

### What the command does

1. Reads the source PNG.
2. Generates the full set of platform-specific icon files in **this directory** (`src-tauri/icons/`), overwriting the existing 16 placeholder files.
3. Updates `tauri.conf.json` if any icon paths are missing from the `bundle.icon` array (the existing five are already there, so no config change is needed for our project).

After the command completes, review the diff (`git diff apps/web/src-tauri/icons/`) — you should see all 16 files modified with the new branded art.

## Recommended Source Location

The **canonical** location for the source icon PNG is the web app's public assets folder, **not** inside `src-tauri/`:

```
apps/web/public/icon-source.png
```

Why `apps/web/public/`?

- It is a Vite-managed static asset root, so designers and CI tooling can reach the file via a stable relative path.
- It lives outside the Rust crate, keeping the source artifact out of `tauri-build`'s inputs.
- It matches the convention used elsewhere in the `generai` repo (hero images, favicons, etc.) — all under `apps/web/public/`.

The source PNG itself should **not** be committed to the repository at this stage. The 1024 × 1024 master file is a designer artifact, not application source. Commit only the regenerated platform variants in `src-tauri/icons/`.

## Workflow

A typical icon replacement looks like this:

1. Export the brand icon as `icon-source.png` (1024 × 1024, opaque PNG).
2. Save it locally at `apps/web/public/icon-source.png` (do **not** commit).
3. From `apps/web/`, run `bun run tauri icon ./public/icon-source.png`.
4. Inspect the regenerated files in `src-tauri/icons/`.
5. Commit the changes under `apps/web/src-tauri/icons/` only.
6. Delete the local copy of `icon-source.png` (or keep it uncommitted in your working tree).

## Note

- Do **not** commit a 1024 × 1024 source PNG. The 16 regenerated platform variants are what `tauri-build` consumes; the master file is a working input, not a deliverable.
- The icon command is intentionally **not** wrapped in a `package.json` script. The plan defers icon generation until the project's brand assets are ready, and a one-off CLI invocation is the simplest interface at this stage.
- If a future task adds a script (e.g. `tauri:icon`) or hooks icon generation into CI, the source path can move to a config file or environment variable. For now, the command above is the source of truth.
